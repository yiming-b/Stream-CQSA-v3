Stream-CQSA 3.0.0: exact out-of-memory recovery for attention, one function with SDPA's signature.

```bash
pip install stream-cqsa                     # pure build (Triton kernels, no compilation)
pip install stream_cqsa-3.0.0-<tag>-<py>-<py>-linux_x86_64.whl   # a CUDA wheel from this page
```

plus the extensions. `python -c "import stream_cqsa; stream_cqsa.doctor()"` reports what loaded and what fits.

**What is new in v3** (details and numbers: `CHANGELOG.md`, `README.md`, `results/v3/`)

* New classic and wave CUDA kernels (census + ALIGNED run tables): 0.77-0.78x flash_attn per task; the
  decomposed forward at 1M tokens runs at 0.98x flash_attn on an A100-SXM4-80GB (v2.2.3: 1.30x), the backward
  in 15 s (v2.2.3: 39 s).
* One extension for both causal modes and both dtypes; routing by a memory model between the monolithic call,
  the wave engine and the classic pipeline; the accumulator in host memory by default where it costs < 15%.
* Grouped-query / multi-query attention on every CUDA route, forward and backward (the Triton fallback
  rejects it with a message).
* Multi-device scheduler (cost-aware split, LPT, reduce-scatter), the E0-E12 measurement series behind every
  number in the README, and the tutorial `notebooks/stream_cqsa_v3_tutorial.ipynb` (executed on an A100).
* The v2.2.3 bug where a pinned `c != 7` silently returned wrong results is fixed here (and in v2.2.4).

869 tests pass as one slurm job (A100-SXM4-80GB, torch 2.10 / CUDA 13). The v2.2.x line stays installable
(`pip install stream-cqsa==2.2.4`); nothing in the one-call API changed between the lines.
