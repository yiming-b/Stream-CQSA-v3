# CITA offline bundle (dist_cita/): progress log

Goal: a self-contained tarball the user untars on CITA (H100, no network; python 3.12.7, torch 2.13.0+cu129,
triton 3.7.1) and runs with no network: `setup_cita.sh` (wheels offline, stream_cqsa in three tiers: Triton /
classic CUDA / wave CUDA), `run_cita.py` (executes `run_cita.ipynb` with nbclient: environment, correctness,
E0, E1 fwd, E1 fwd+bwd, E3 fwd, E4, E6, report, results tarball). Spec: the task message of 2026-10-22.

## 2026-10-22

- Read setup.py (CQSA_SKIP_EXT / CQSA_KERNEL_SET=common / CQSA_BUILD_NATIVE / CQSA_ONLY_NATIVE; in-place
  build puts `cqsa_cuda.*.so` and `cqsa_native.*.so` at the source root; interface.py tries cqsa_cuda_v13
  then cqsa_cuda, native_wave.py cqsa_native_v2 then cqsa_native), bench.py (argparse: --ref fa2|spot only;
  FA-2 reference = flash_attn; the FA-2 arm imports flash_attn), tests/_decomp.py, doctor.py.
- FINDING: the pip wheel `nvidia-cuda-nvcc-cu12==12.9.86` contains ONLY `bin/ptxas`, `nvvm/` (libnvvm,
  libdevice) and `include/crt`: no `nvcc`, no `cicc`, no `cudafe++`. The `cuda-toolkit==12.9.1` pip
  metapackage depends on the same wheel. So CITA's venv has NO nvcc from pip; tiers (b) and (c) need a system
  CUDA 12.x toolkit (`nvcc` on PATH, CUDA_HOME, /usr/local/cuda*, or a `module load cuda/12.x`). torch's
  cpp_extension refuses an nvcc whose major version differs from torch.version.cuda (12.9): a CUDA 13 nvcc
  cannot be used with torch 2.13+cu129.
- FINDING: with no CUDA extension loaded, `attention(kernel="cuda")` silently runs the Triton inner kernel
  and reports kernel="cuda" (stable_stream.py:1334); `kernel="wave-cuda"` without cqsa_native raises. The
  notebook therefore derives the series list from `stream_cqsa.kernels_available()` and never runs
  classic_CUDA / wave_CUDA rows on a Triton-only install.
- bench.py: `--ref sdpa`; `resolve_ref_arm()` maps the plan's "fa2" to SDPA-flash when flash_attn is not
  importable; `sdpa_flash_reference()`; every row records `ref_arm`; the report has a `ref` column and labels the
  error columns "vs ref"; cmd_run drops the FA-2 arm rows with a notice when flash_attn is missing; gpu_info reads
  a GIT_COMMIT file of a frozen snapshot. Smoke on vis1 (E0, classic_Triton, `--ref sdpa`): 4 rows ok,
  ref_arm=SDPA-flash, rel 2.2e-3 (bf16) / 2.9e-4 (fp16 D128); the Della report regenerates unchanged in content.
