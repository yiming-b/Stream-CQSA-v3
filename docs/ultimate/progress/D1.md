## Split unit (decision)

Row/column spans cannot run today: the CQS group-bits entry points require `seqlen_q == seqlen_k`
(v11 `flash_api.cpp:771` forward, `:1862` backward) and the wave kernel has no row range, so a span needs
the row-range launch parameter (kernel dependency **U1**). The scheduler models spans (`split="rows"`,
equal live work per span, K/V prefix counted as gathered tokens) for planning only; the driver refuses
them with a message naming U1.

What the engine CAN run today is child refinement: `refine_task`'s `c` children of a task are the tasks
`build_tasks(itr+1)` builds at paths `parent.path + (j,)` (path_idx = parent*c + j), and their retained
pairs partition the parent's exactly (the OOM escalation relies on it). Measured on the model: under the
128-aligned layout the children's live 128x128 tiles sum to the parent's EXACTLY (N=131072 and 1M, causal
and not, children and grandchildren; test `test_children_partition_parent_work_and_match_the_engine`),
so a split costs no pair work, only c-1 launches (~3 ms each) and l x the parent's gathered tokens. A
rank holding units at two depths makes one engine call per depth (`task_subset` at that depth) and the
cross-rank merge folds all its partials. The shared chunk pool is itr=1-only, so the depth-2 call drops
it (the strict and adaptive layouts give identical tasks at refinable levels; tested). Verified on the
CUDA kernel (vis1, two ranks on one GPU): split forward rel 2.6e-5 vs the single-device engine, float64
error identical (2.03e-4 on the last 256 rows); backward rel 2.8e-4.

## Scheduler as built (`stream_cqsa/scheduler.py`)

- Work = live 128x128 tiles per task from the task's group bits (census definition: masked iff
  `and_i & and_j != 0`, causal lower triangle incl. diagonal), O(nb * U) via the few distinct block
  values; equals the brute-force census on every task tested. NOTE: `task.extra["blk_and"]` is at
  `CQS_BLK_SIZE` = 64 rows; the model rebuilds the summaries at 128.
- Measured work spread (1M, c=7, aligned): itr=1 tasks equal within 0.1%; itr=2 tasks differ by 1.76x
  (502K..882K live tiles): round-robin's 49-on-4 is 1.037x the ideal by luck, plain LPT 1.042x.
- Cost on rank r: `tiles * B*H * d_factor / rate_r + task_s + L * tok_s * (B*H*D/512)`; `d_factor` = 1.78
  at D=128 (fwd_ab: 31.80/17.88 ms), x3 for the backward.
- LPT (units by cost on the slowest rank; earliest predicted finish among ranks whose budget admits the
  unit; ties to the lower rank) + a move/swap descent on the most loaded rank (49 unequal itr=2 tasks:
  1.042 -> 1.0001x) + refinement: while makespan > 1.05 x ideal, split the largest untried splittable
  unit of the most loaded rank (children, <= 2 extra depths, L >= c*128) and keep the split if the
  descending load vector improves lexicographically (or is exactly equal: 7 tasks on 8 ranks need every
  task split before the max can fall).
- Memory: `base_bytes` (accumulator) + `depth_bytes` per extra depth + n_par x the largest unit's working
  set (`estimate_task_bytes`) <= the rank's budget; a unit nobody can hold is split first; else Infeasible.
- Deterministic (pure function; digest identical across processes with different hash seeds, test); the
  driver all_gathers the rate table and the digest and refuses a mismatch.
- Model results (4 ranks, 1M, c=7; tile rate 3e7): itr=1 equal ranks rr 1.143 -> lpt+children 1.015;
  rates (1,1,0.67,0.67): rr 1.426 -> 1.021; itr=2 equal: rr 1.037 -> 1.0001; itr=2 (1,1,1,0.5): rr 1.707
  -> 1.002; 8 ranks itr=1: 1.143 -> 1.033 (2M: 1.015). Synthetic 7 equal tasks: 4 ranks 1.0029,
  (1,1,0.67,0.67) 1.022, 3/5/8 ranks <= 1.041.

## Driver as built (`stream_cqsa/distributed.py`)

`dist_stream_cqsa_forward/backward(..., scheduler="lpt"|"rr", split="auto"|"children"|"none",
reduce="allreduce"|"reduce_scatter", output="replicated"|"sharded", rate=, budget_bytes=, tol=0.05,
max_extra_depth=2, chunk_tokens=256K)`; `plan_distributed()` is the dry-run entry point; `rank_table()`
all_gathers (rate, budget, GPU, source); `merge_forward()` / `reduce_gradients()` are the reductions.
- allreduce: per token chunk one all_reduce(MAX) of lse + ONE all_reduce(SUM) of the packed (w*out, w)
  (the old code made two SUM calls), result written in place into the first partial (the old code
  allocated a second full fp32 output and 1M-token chunk temporaries).
- reduce_scatter: rank r owns [rN/W, (r+1)N/W) (uneven N padded per step); per step one all_reduce(MAX)
  of the lse of every rank's next piece, one reduce_scatter(SUM) of the stacked pieces, one all_gather of
  the lse piece (the global lse is returned whole); `output="sharded"` returns [B,H,hi-lo,D],
  "replicated" all_gathers the pieces. Backward: one reduce_scatter per gradient step.
- `output="sharded"` now returns only the rank's range (was: full size, zeros elsewhere; no caller used it).
- gloo works (CPU tensors, or CUDA partials staged through host memory: D2H copies are blocking there --
  a non_blocking D2H read before the copy landed gave 5% errors in the first two-rank run).
